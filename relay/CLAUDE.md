# relay/

The collaboration relay (`docs/architecture/collab.md`). It is its own npm project and depends only on `ws`; the root keeps `ws` as a dev dependency for `tests/relay.test.ts`.
`npm run relay` in the root starts it on port 4390, and the Vite dev server proxies `/relay` to it (`RELAY_PORT` to change it).

- Protocol: a WebSocket on `/relay`. The first frame is text, `{"t":"hello","v":1,"room":"<id>","token":null}`. The room is a hash of the session key, never the key itself. The answer is `{"t":"welcome","peers":n,"frame":MAX_FRAME,"beat":BEAT_MS}`, or `{"t":"full"}` and close code 4001. A bad hello closes with 4000, too many rooms with 4003. Everyone in a room gets `{"t":"peers","n":…}` when someone comes or goes.
- Binary frames go unchanged to everyone else in the room. They are AES-GCM ciphertext, so the relay cannot read them. Text frames after the hello are dropped.
- Addressing: a hello may carry `"id"`, the client's random session id (1 to 2³²−1; anything else closes with 4000). The welcome then says `"to":true`, and every binary frame of that client starts with the receiver's id, 4 bytes big-endian in clear before the ciphertext, 0 for everyone. The relay strips it and passes the rest to that client alone, or to all; a frame to an id not in the room is dropped. A client dialling again with its id takes it over from its old socket. When the id's current socket closes, the `peers` message says `"gone":id`, so the others drop that client at once instead of after awareness's 30 s.
- Every `beat` ms each client in a room gets `{"t":"beat"}`. Browsers cannot see WebSocket pings, so a client that hears nothing for three beats drops the line as dead (half-open) and dials again; without `beat` in the welcome it never does.
- `frame`, `beat`, `id`, `to` and `gone` were added without a new `v`: clients ignore fields and messages they do not know, and against a relay without `frame` a client splits at 1 MiB. A client without `id` gets every frame as before; one whose welcome lacks `to` sends frames without the receiver in front, and each receiver drops those not meant for it, since the sealed message names its receiver too. Clients split longer messages into sealed parts themselves (`src/lib/collab/channel.ts`), so the relay never sees a message, only frames.
- The relay cannot tell readers from writers: both links of a session (`#collab=`, `#view=`) lead to one room, readers count toward `MAX_PEERS`, and only the clients check the writers' signatures.
- Nothing is stored: a room is a set of sockets in memory and disappears with its last client. No content and no room id is logged. What the relay still sees: addresses, times, frame sizes, how many share a room, and which random session id sends to which.
- Limits from the environment: `PORT`, `HOST`, `MAX_PEERS` (6, as measured in `docs/architecture/collab-soak.md`; 0 = none), `MAX_FRAME` (bytes per frame, 16 MiB; larger closes with 1009; clients send at most 1 MiB), `MAX_ROOMS`, `BEAT_MS` (15 s; 0 = none), `PING_MS` (5 s): a connection that misses a ping round is dropped, so a closed laptop or dead network leaves its room, `gone`, within two rounds. `/health` answers `ok`.
