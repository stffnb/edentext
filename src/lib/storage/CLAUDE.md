# `src/lib/storage/`

The autosaved document (`autosave.ts`) stays **plain text** even when the document is
password-protected: the protection is on the saved file, not on the browser copy.

## Page layout settings

- **`pageMargins.ts`** — `PageMargins` in **cm** (default `{ top: 2, bottom: 2, left: 2, right: 2 }` — LibreOffice's; `fitMargins` only caps an imported pair at what leaves the page a 1cm strip of text). `applyMarginVars` sets `--user-margin-*` (px) on `:root`; `PX_PER_CM = 96/2.54`. Optional `mirrored` (ODF `style:page-usage="mirrored"`, Word `w:mirrorMargins`) makes left/right the **inner/outer** pair, which an even page swaps: `Editor.svelte` publishes the difference per section as `--pb-section-mirror` (a cover between mirrored pages mirrors nothing), `pageBreaks.ts` insets an even page's blocks by it and `HeaderFooterLayer.svelte` moves the band. The key is **absent**, never `false`, when off — margins are compared whole in the round-trip tests, which is what `withMirrored` is for; `marginAxisLabel` gives both margin UIs the Inner/Outer field names that go with it. A margin edit in either UI (and the assistant's `setPage`) goes through `spreadMargins` (`headerFooter.ts`): the values that changed reach every section with margins of its own, or an imported book's chapters would not move. **Which side a page is on comes from its printed number** (`pageNumbering.ts`'s `printedPageNumber` + `isLeftPage`), not its sheet: probed, LibreOffice calls a page left when its number is even, so a section restarting on the other parity really does show two left pages in a row. The mirror inset, the page border and the odd/even zone all read it.
- **`tabInterval.ts`** — the document's default tab interval in **cm** (`DEFAULT_TAB_INTERVAL_CM = 1.25`, LibreOffice's for a new document; clamped 0.05–10). `applyTabIntervalVar` sets `--tab-interval`, which is `.tiptap`'s `tab-size`. A file that declares none falls back to its format's own value, neither of them ours: `ODF_IMPLIED_TAB_CM` 2cm (measured against LibreOffice), `DOCX_IMPLIED_TAB_CM` 1.27cm — so both exports always write the value out.
- **`spacingModel.ts`** — how the gap between two blocks is measured: `'add'` (LibreOffice's
  own — space-below **plus** space-above) or `'max'` (the larger of the two, what it uses for a
  Word document). Probed against soffice; per document, read from ODF `settings.xml`
  (`AddParaTableSpacing`), always `'max'` on DOCX import, and written back on ODF export.
  `editor.css` turns `--space-before` into padding or margin accordingly (CSS margins can
  only collapse, so `'add'` cannot be a margin). The same module holds **spacing at a page
  start** (`AddParaTableSpacingAtStart`, Word's `w:suppressSpBfAfterPgBrk` read the other
  way): off, the block that opens a page loses its space above however the page broke —
  probed by flipping the flag in one document, whose heading then moved 25.4mm → 20.0mm.
  On is the default both products write, and `pageBreaks.ts` reads it as
  `--pb-space-at-page-start`.
- **`writingMode.ts`** — the page's text direction (`loadPageRtl`/`savePageRtl`, `edentext-page-rtl`), from ODF `style:writing-mode="rl-tb"` or Word's section-level `w:bidi`. `Editor.svelte` puts it on the body host as `dir`, which is what makes a multi-column page fill from the right; the header/footer band is left alone (LibreOffice lays those out unchanged — measured). The vertical modes are not read.
- **`pageNumbering.ts`** — the page-number field's format and start value (`edentext-page-numbering`, absent at the 1/1 default). `HeaderFooterLayer.svelte` formats each page through `formatOrdinal`; the page **count** stays decimal, as the field both word processors write does. ODF keeps the format on the page layout and the start on the first paragraph's own style (`style:page-number` — probed, ODF has no document-level start); Word keeps both in the first section's `w:pgNumType`. A section can also demand the **side it opens on** (`HfSet.startsOn`, ODF `style:page-usage` right/left — read only where the master is no half of a mirrored pair — Word's `w:type` oddPage/evenPage): `pageBreaks.ts` holds its first page back by one where its **sheet** is the other side, which is the blank page both word processors insert — not the printed number: LibreOffice pads a restart at 1 onto an even sheet (probed). A **later section** can restart the count (`HfSet.pageNumberStart`): ODF writes `style:page-number` on the same paragraph that switches master page, Word a `w:pgNumType w:start` — and that section is then exported as a page-starting break, since both word processors ignore a start on a continuous one (probed: LibreOffice drops it).
- **`hyphenation.ts`** — automatic hyphenation for the whole document (`edentext-hyphenation`, off by default as in both word processors). `Editor.svelte` puts `hyphens: auto` and the document `lang` on the body host — the browser needs the language to pick its patterns. ODF keeps it as `fo:hyphenate` in the **text** properties of the base paragraph style (probed: in paragraph-properties LibreOffice ignores it and drops it on the next save), Word as `w:autoHyphenation` in settings.xml. A **paragraph** can only opt *out* (`noHyphenation`, pageBreak.ts): Word has no per-paragraph "on", and both importers drop the flag under a document that does not hyphenate, where it says what is already true.
- **`wordCompletion.ts`** / **`.svelte.ts`** — the word-completion settings *and* the collected words (`edentext-word-completion`), LibreOffice's defaults: on, no appended space, words from eight letters, 1000 of them. The list outlives the document that filled it, as LibreOffice's profile copy does; a reactive singleton, since the extension both reads it and adds to it on every keystroke while the AutoCorrect dialog edits it.
- **`autoText.ts`** / **`.svelte.ts`** — the AutoText library (`edentext-autotext`, the key removed when empty): name, shortcut and the entry's nodes (an older entry's HTML string is read as the content it is). App-level, not document-level, so no exporter looks at it.
- **`tableOptions.svelte.ts`** — table number recognition (`edentext-number-recognition`, the key removed when off, as it is by default in LibreOffice). A reactive singleton like `trackChanges.svelte.ts`: the extension reads it on every transaction, both table surfaces flip it. It also holds the **number locale** — the document's language, which is what LibreOffice reads and writes a cell's number in — pushed by `App.svelte`'s language effect; the exporters take that locale from their own `language` argument instead, so they stay store-free. See `docs/architecture/tables.md`.
- **`pageDecor.ts`** — the page's own decoration (`edentext-page-decor`, the key removed when all three are off): background colour, a border around the text area at `paddingCm` from it, and a text watermark (LibreOffice's Format ▸ Watermark, field for field). All three ride the ODF page layout — the watermark as a `fontwork-plain-text` `<draw:custom-shape>` named `PowerPlusWaterMarkObject` in the **master page's header**, the only place LibreOffice reads one from (probed: hung off the master page directly it is dropped, and an undeclared `xmlns:draw` in styles.xml drops it too). Word keeps the background on `w:document` (plus `w:displayBackgroundShape`), the border in `w:sectPr` **after `w:pgMar`** — the child order is fixed, and ahead of the header references Word's reader loses those — and the watermark as the VML `_x0000_t136` shape, whose definition has to travel or LibreOffice cannot resolve it. `PageDecorLayer.svelte` draws border and watermark per page; the background is a `--color-page-bg` override on `.paper`. ODF lays border + `fo:padding` out *inside* the page margin, shrinking the text area — the editor and Word (`offsetFrom="text"`) keep text at the margin — so the ODT export shrinks every `fo:margin-*` by border + padding and the import grows them back (`decorInsetCm`).
- **`trackChanges.svelte.ts`** — whether the **document** records revisions (`edentext-record-changes`, the key removed when off, as it is by default in both word processors). `edentext-record-lock` holds what protects that (`docs/architecture/review.md`), and a lock refuses `setRecordChanges(false)`. It travels with the file — ODF `text:track-changes` on the change registry, Word `w:trackRevisions` in settings.xml (both probed against soffice) — so an import adopts the file's flag and a new document starts off; only the open document's state lives under the key. A reactive singleton because the extension reads it on every transaction while the Review tab flips it; the recorded changes themselves live in the document, on the marks.
- **`lineNumbering.ts`** — numbers in the left margin (`edentext-line-numbering`, the key removed when off, as it is by default in both word processors). ODF keeps one `<text:linenumbering-configuration>` in `office:styles`, Word a `<w:lnNumType>` per `w:sectPr` (probed). `LineNumberLayer.svelte` measures the lines: CSS exposes no line boxes, so a Range per block is taken and its distinct client-rect tops are the lines.
- **`lineGrid.ts`** — the page's line grid (`edentext-line-grid`, removed when off): every line on it is rounded up to whole grid lines (`round(up, …, --grid-pitch)` in `editor.css`) — one exactly a pitch tall takes two, as Word gives 12pt SimSun on a 15.6pt grid — a fixed spacing, a block with `snapToGrid: false`, a zone and a text box excepted. Word `<w:docGrid w:type="lines" w:linePitch>`, ODF `style:layout-grid-mode="line"` + base height on the page layout with `layout-grid-standard-mode` on the default page layout, as LibreOffice writes Word's (probed). Only the line half; the character grid is not modelled.
- **`balanceSpaces.ts`** — every space at half the font size (`edentext-balance-spaces`, removed when off, as it is by default in both word processors): Word's compatibility option `w:balanceSingleByteDoubleByteWidth`, ODF `BalanceSpacesAndIdeographicSpaces` in settings.xml. Probed in LibreOffice: every U+0020 is then 0.5em, with or without an Asian font. `.paper[data-balance-spaces]` sets `--font-space` to the bundled half-width face (`EdenSpace.woff2`, Liberation Serif's space with a 0.5em advance, `unicode-range: U+20`), which every font stack puts first — being the stack's first font it also gives the line its metrics, hence Liberation's.
- **`documentLanguage.ts`** — the document's spell-check language (`edentext-doc-language`, doc-scoped), plus the other slot's tag (`edentext-doc-language-other`: the western default of an East Asian document or the asian one of any other; `pickDocumentLanguage`, `westernCode`), one `LANGUAGES` entry per bundled Hunspell dictionary under `public/dictionaries/<code>/`. New, New from Template and a file that names none reset it to `defaultDocumentLanguage()`, the browser's, as a first run starts. `en` and `en-GB` differ only in `odf.country`, which is what makes an imported `en-GB` document check British; the two share the `en` thesaurus (`spell/thesaurus.ts`). A `noDict` entry (`zh-CN`, `zh-TW`) is a language the document can be **in** without a dictionary: the picker offers it so the file names its language — a file that names none reads as English in Word — and `hasDictionary` keeps both loaders from fetching a 404.
- **`spell/grammar.svelte.ts`** (not in this folder, same shape) — `edentext-grammar-check`, app-wide and **not** doc-scoped, the key only written at its non-default **on**. `LanguageDef.grammar` in `documentLanguage.ts` is what says a language has a grammar engine at all; the switch greys out without it.
- **`spell/detect.svelte.ts`** (same shape) — automatic language detection, `edentext-auto-language`, app-wide, the key only written at its non-default **off**. Checking only: a textblock with no `lang` of its own is checked in the language franc-min proposes and the dictionaries confirm (the candidate's must know ≥75 % of the words and 25 points more than the document language's), from 40 characters on; a verdict is cached per node, so a long document reads each paragraph once and an edit only its own. The picker's "Apply detected language" is the only path that writes it into the file.
- **`printMarkup.svelte.ts`** — whether a printout carries the review markup (`edentext-print-markup`, the key removed at its **on** default, so it is the off state that is stored — the switch both word processors offer). A reactive singleton like `trackChanges.svelte.ts`: the Review tab flips it, all three export paths read it. What it governs lives in `export/reviewPrint.ts`.
- **`markup.svelte.ts`** — the whole review view. The mode (`edentext-markup-mode`, absent at `all`) is Word's four steps — *all* (every change marked up), *simple* and *none* (the final text, the second without bars, cards or lists), *original* (the text before the changes). Per kind it holds whether it shows (`edentext-markup-comments`, `edentext-markup-changes`) and **where** its cards go (`edentext-markup-comment-place`, `edentext-markup-change-place`, absent at `balloons`) — beside the line or in the pane, which is why no separate pane flag exists any more. Resolved comments keep their folded, greyed cards unless `edentext-markup-resolved` is `false`; the rule is `visibleComments` in `components/reviewItems.ts`. The two are tied: picking a mode carries both kinds with it, and switching a kind on lifts a mode that hides everything back to *all*, so no button is left claiming what the page does not show. `markupView()` folds it into what the page and the layers act on, read once instead of re-derived at every call site; Settings ▸ Review shows the two kinds and their places through the same setters as the Review tab. `markupAttrs()` is the same view as `.paper` attributes, for the print path that builds its page from scratch. Both formats keep the choice out of the file — it is a view, like zoom.
- **`foldMarks.ts`** — fold + punch marks in the left margin (`edentext-fold-marks`, the key removed when off; neither word processor prints any by default). The DIN 5008 positions (87/192mm folds, 148.5mm punch) are this module's constants; `FoldMarkLayer.svelte` draws them per page — the folds on **both** edges (both hands find the crease), the punch mark only left, where the pages are filed. They export as named lines (`EdenFoldMark*`) in the master page's header — the one place that repeats on every page, where LibreOffice's own DIN templates keep them — ODF as page-relative `<draw:line>`s, DOCX as VML `<v:line>`s; both importers read the names back into the flag and never into the zone's content. The flag is the user's wish; `App.svelte` derives `foldMarksOn` from it (A4 portrait only, the paper DIN 5008 describes) and hands *that* to the layer and both exporters, which is what keeps an imported or templated flag from drawing marks off a Letter or landscape page. The Layout button greys out there.
- **`pageOrientation.ts`** — `'portrait' | 'landscape'`. `applyOrientationVars` sets `--user-page-{width,height}`; landscape swaps the A4 dimensions (matching odf-kit's automatic swap).
- **`pageFormat.ts`** — the paper (`edentext-page-format`, also `HfSet.format` per section): a named format, or a custom `"<w>x<h>"` portrait box in cm where a file's size matches none (`pageFormatOf`, 0.2 cm tolerance), kept to 0.1 mm when that is within half a twip, else 0.01 mm, so both imports write the same size back. The paper menus list a custom size as the selected extra entry, and take a typed width and height (`sizeSetup`, 1–600 cm): a box equal to a named format is that format, and the longer side sets the orientation; the AI's `set_page` takes the same `<w>x<h>` box.

Both margins and orientation are passed into the ODT export so the exported document's geometry/line-wrapping matches the on-screen preview.

## localStorage keys

All keys share the `edentext-` prefix — a namespace, not a description: on GitHub Pages every repo of an account shares one origin, so a generic prefix would collide.

**Document scope (`docScope.ts`).** Every key below that belongs to the *document* is
written through `docKey()`, which appends `@<id>` — that is how two tabs edit two
documents. The **first document keeps the empty id**, so its keys read exactly as this
list spells them and no earlier version needs migrating. The id comes out of
`sessionStorage` (per tab, survives its reloads); a fresh tab always gets a new, empty
document, as a word processor starts on an empty page. A tab **holds** its document by the
Web Lock `edentext-doc@<id>`, which the browser releases however the tab ends — a crash or
a quit fires no `pagehide`. `edentext-live@<id>` is the marker — epoch ms while held,
negated on `pagehide`, refreshed every 60 s: the last use, and where Web Locks are missing
(an insecure origin) the hold itself, abandoned after 10 min. Only the holding tab ever
writes its own marker, so no two tabs race over one key.
`pruneOldDocuments()` (from `main.ts`) first drops every document no tab holds unless documents are kept, this tab's own when `volatile`, and a protected one always, since its copy here is unencrypted; their pictures are swept at once, and `listDocuments` waits for the prune. Then it drops every empty document no tab holds, then all but the newest ten — never a held one, and the first never for its age. While the page is empty, `ResumeCard.svelte` offers the three used last. Duplicating a tab copies its `sessionStorage`, so the copy lands on the same document — the one case still shared. File ▸ *Recent documents* (`BrowserDocumentsDialog.svelte`) lists every marker: opening one points this tab's `sessionStorage` at it and reloads, deleting one drops its keys — the first document's by the names `docKey()` has registered, since its keys carry no id. Neither touches a held one. The app's own keys (theme, zoom, chrome, AutoCorrect, AutoText, word completion, recent files/fonts/chars, markup view, user dictionary, number recognition) stay unscoped.

- **Keep documents:** `edentext-keep-documents` — app-wide, the three choices in `SettingsDialog.svelte` (the ribbon's gear): absent = keep, `'0'` = drop closed documents at the next start, `'none'` = store nothing. `volatile` is read once at load (and is always on in embed mode, `docs/architecture/embed.md`), so `'none'` takes effect at the next start: every document key then goes through `docStore`, a Map in memory instead of localStorage, and `saveDocument`, the font store, the tab's `edentext-live@` marker, recent files, collected words, the user dictionary, `ResumeCard` and File ▸ *Recent documents* are all off — the menus list no recent file, though Settings can still clear the old list — a reload starts empty. `docScope.ts`'s own readers (`markers`, `storedDoc`, `isEmpty`, `labelOf`, `dropDocument`) read other documents and stay on localStorage.
- **Document:** `edentext-doc` — TipTap JSON without the attributes at their schema default (`withoutDefaults`; a paragraph otherwise spells out some thirty, mostly null, and loading fills them back in), debounced 1 s on every `onUpdate` and serialized only when the write runs (`autosave.ts`); hiding the page (`visibilitychange`/`pagehide`) writes what is pending at once, and writes queue behind each other so a slow picture round trip never stores an older document over a newer one. Loading it raises `edentext-doc-loading`, which only a completed startup clears (`markDocumentLoaded`, two frames after `Editor.svelte`'s mount). Still set at the next load = that document hung or crashed the editor, or a reload cut its start short: the user is asked whether to try again; declined, it moves to `edentext-doc-broken` and the kept versions are offered before the app starts empty, so a freeze is escaped instead of repeated. Starting empty (or from an unreadable copy) calls `loadDocument`'s `onLost`, which is `App.svelte`'s `resetDocumentState` — the side-car keys are written at once and the document a second later, so without it the lost document's margins, headers and styles live on in the empty one. **Pictures do not live in it:** `imageStore.ts` swaps every data-URI past 4 KB for an `idb:<key>` before the write and keeps the bytes in the `edentext-images` IndexedDB store (a handful of photos is the whole localStorage quota). The key is a content hash of the data-URI's head, tail and length — sampled, because this runs on every autosave — so a picture used twice is stored once, across documents too — which is why the store is the one thing **not** scoped per document. Each save sweeps the keys no stored document names any more, found by scanning localStorage for `idb:` references rather than by a per-document list, which would go stale for every document no tab has opened since. The pagehide flush stashes only keys the store has confirmed this session (`isStored`) — a picture just imported may never land before the tab dies — and falls back to all keys when the inline copy overflows the quota. Where IndexedDB is unavailable the data-URIs stay inline, exactly as before; a key the store has lost keeps its `idb:` src and is reported, rather than quietly dropping the reader's content. `loadDocument` is therefore **async**, and `Editor.svelte` awaits it before building the editor.
- **Earlier versions:** the `edentext-snapshots` IndexedDB database (`snapshots.ts`, one per document via `docKey`, as `edentext-fonts` is) — up to three earlier autosaves, one taken at most every five minutes, keyed by their timestamp. They hold the document **whole**, pictures inline: the image store is swept against the stored documents, and a snapshot is none of them. **Nothing in the UI points at them**: they are offered only where the browser copy has failed the reader — `loadDocument`'s recovery question, newest first, one confirm each (the newest may be the one that broke). A version taken up starts under the boot flag like any other document, so one that freezes the editor again brings the question back.
- **Recent files:** `edentext-recent-files` — `{id, name, at}` per entry, newest first, eight kept (`recentFiles.ts`). Only the label lives here: the `FileSystemFileHandle` that reopens one is structured-cloneable but not JSON, so it sits in the `edentext-recent` IndexedDB store under the same id, and each write sweeps the handles no entry names. Two handles compare only through `isSameEntry`, which is async — hence the walk when recording a file already in the list. A file without a handle is never recorded (nothing could reopen it — no File System Access API, or a template), so the list simply stays empty in Firefox/Safari/Brave; a startup prune drops entries whose handle is gone. Reopening asks for `read` permission again (the API drops it on reload) — a declined prompt keeps the entry for the next try, only a moved or deleted file drops it (with a message). Save re-prompts for write on its own (Save-As fallback in `App.svelte`). The desktop app's documents opened by the system are path handles (`desktopFiles.ts`), stored as `{path}` and compared by path.
- **Document protected:** `edentext-doc-protected` — `'1'` while the open document is password-protected; the password itself is never stored, so after a reload the first save asks for it again or lets the protection go (`documentName.ts`).
- **Document file:** `edentext-doc-file` — `{id, modified}`: the recent-files id of the file the document was last opened from or saved to, and its `lastModified` then (`documentName.ts`). A reload restores the handle from the recent store, so Save keeps writing there (asking for `readwrite` in the click); a file changed since asks before it is overwritten, declining goes to Save As. Gone with the handle once the recent list drops it.
- **Document format:** `edentext-doc-format` — `'docx'` while the open document round-trips as .docx; absent = .odt (`documentName.ts`). Set by the format a file was opened in, and by the extension picked in Save As.
- **Theme:** `edentext-theme` — `'light' | 'dark' | 'allBlack' | 'auto'`.
- **Accent:** `edentext-accent` — one of `ACCENTS` (`theme.ts`) or a custom `#rrggbb`, which `applyAccent` sets as an inline `--brand-slate` under `data-accent="custom"`; absent = `slate`, the logo's.
- **User name:** `edentext-user-name` — the name on new comments, replies and recorded changes, for this browser and not per document (`userName.svelte.ts`, Settings ▸ Review), asked for by `ensureUserName` (`components/reviewItems.ts`) before a comment, a reply, recording or a compare, and on opening a file that records, since a record keeps its name for good; absent when empty, and then they carry no author. A document's `author` property only says who wrote that file; Merge alone records under it, as the other file's author.
- **Date format:** `edentext-date-format` — absent = `auto`, the UI language's convention; else a region tag of `DATE_FORMATS` or `iso` (`dateFormat.svelte.ts`, Settings ▸ General). `formatMoment` writes every moment a reader sees in the app (comment and change cards, the review print, kept versions, the browser's document list); a date field in the document keeps its own picture.
- **Toolbar expanded:** `edentext-toolbar-expanded` — boolean string.
- **Toolbar category:** `edentext-toolbar-category` — the island's Tools category (`toolbar/island.ts`), Home when unknown.
- **Chrome:** `edentext-chrome` — `'modern' | 'ribbon'` ('classic' read as the modern island's legacy stored name); absent = ribbon.
- **Ribbon collapsed:** `edentext-ribbon-collapsed` — boolean string; absent = expanded.
- **Formatting marks:** `edentext-formatting-marks` — boolean string.
- **Ruler:** `edentext-ruler` — boolean string; absent = on, off at ≤600px width.
- **Page labels:** `edentext-page-labels` — boolean string; absent = on. The sheet number beside each page's bottom right corner (`PageLabelLayer.svelte`, Settings ▸ View); a view, never exported or printed.
- **Split view:** `edentext-split` — boolean string; absent = off. The divider's position is not kept, as neither word processor restores one.
- **Pages side by side:** `edentext-page-columns` — how many, 1–`MAX_PAGE_COLUMNS`; absent = 1. Only one pane layout at a time, so turning this on ends the split.
- **Zoom:** `edentext-zoom` — integer percent.
- **Page margins:** `edentext-page-margins` — JSON cm values.
- **Page orientation:** `edentext-page-orientation` — `'portrait' | 'landscape'`.
- **Tab interval:** `edentext-tab-interval` — cm as a decimal string.
- **Spacing model:** `edentext-spacing-model` — `'add' | 'max'`.
- **Balanced spaces:** `edentext-balance-spaces` — `'true'`; absent = off.
- **Recent fonts:** `edentext-recent-fonts` — JSON string array (ToolbarExpanded).
- **Download hint shown:** `edentext-download-hint` — set by the first fallback download (`export/saveFile.ts`); the one-time "always ask where to save" hint.
- **Header/footer:** `edentext-header` / `-footer` (HfDoc, a zone-schema doc of any blocks; refitted to the schema on load), `edentext-hf-distances`. Their pictures and `edentext-hf-sections`' go to the image store too: a save writes at once, by key for pictures the store has confirmed and inline for the rest, then again by key once `putImages(…, false)` has them — keys it pins against this session's sweeps. The zones load synchronously, so `App.svelte` swaps their pictures back in afterwards (`loadHfPictures`), unless a reset or an opened file replaced the zones meanwhile. A write that overflows the quota, body or zone, ends in the one `warnStorageFull` warning per session; where the browser keeps other documents it says to delete them under File ▸ Recent documents.
- **Styles:** `edentext-styles` — the style registry (`styles/sheet.svelte.ts`).
- **Document properties:** `edentext-doc-properties` — title/subject/author/keywords/comments (`docProperties.ts`); the key is removed when every field is empty, so a fresh document writes nothing into `meta.xml`.
- **AutoCorrect:** `edentext-autocorrect` — one flag per rule (`autoCorrect.ts`, reactive singleton in `autoCorrect.svelte.ts`), LibreOffice's defaults (all on).
- **Navigator:** `edentext-navigator` — JSON `{open, side, size, width, wrap, tab}` (`navigator.svelte.ts`), app-wide: the pane's view, never the document's.
- **Reviewing panes:** `edentext-panes` — JSON `{comments, revisions}`, each `{side, size, width}` (`panes.svelte.ts`, whose `validLayout` the navigator's load shares).
- **AI assistant:** `edentext-ai` — JSON `{enabled, provider, endpoint, apiKey, model}` (`ai.svelte.ts`), app-wide; removed while on and empty, so switching off is stored. `enabled` is the kill switch, on by default so the button is found; nothing goes out before a provider is set; switching off keeps the provider. The key is stored in plain text; in embed mode `setAi` keeps it in memory only. See `docs/architecture/ai.md`.
- **Notes:** `edentext-notes` — footnote/endnote numbering and the separator (`noteSettings.ts`, reactive singleton in `notes.svelte.ts`); `applyNoteVars` puts the separator on `:root`, where `editor.css` draws it and `pageBreaks.ts` reserves its band.

## Themes (`theme.ts`, `styles/global.css`)

Four modes: `light`, `dark`, `allBlack` (forces font colors white), `auto` (follows `prefers-color-scheme`). Applied by setting `data-theme` on `<html>`; CSS variables for each theme live in `global.css`. An inline script in `index.html` sets it and each theme's background before the module loads and hides the static intro, so the first paint never flashes white (keep its colours in step with `--color-bg`); `applyTheme` also sets the `theme-color` tags to the picked theme's background, since their media query only knows the system scheme. The sheet keeps its own pair through light and dark — white paper, **black** text, the colour LibreOffice and Word draw an uncoloured run in (the app's slate would also differ from a run the file colours `#000000`); only `allBlack` inverts it. A picked **accent** (Settings ▸ General) sets `data-accent` on `<html>`, which swaps `--brand-slate` and mixes the ribbon's accent shades from it; the slate keeps its hand-tuned shades and no attribute.
